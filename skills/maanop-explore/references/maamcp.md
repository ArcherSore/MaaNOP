# MaaMCP 使用与预算检查

首次使用或版本/窗口变化时读取。数值预算只在根目录 `AGENTS.md` 维护；本文件说明检查方法，不提供固定版本的调用契约。

## 工具与坐标

- 从当前工具 schema 确认 `screencap`、`ocr`、`run_pipeline` 的参数，检查实际返回字段。不要因为上游 README 出现 `include_metadata`、`target_short_side`、`pipeline_override` 或 `timeout_seconds` 就向旧工具发送这些参数。
- MaaMCP 工具环境版本、运行中的服务进程版本、项目 `.venv` 的 maafw 分别确认。更新磁盘包不代表已连接进程已重启；无变化时复用本轮记录，不反复枚举。
- 控制器可能已经缩放到某短边；控制器完整截图坐标不一定是设备物理坐标。记录完整截图尺寸、模板适用尺寸和图像变换依据，不假定 1280×720 或 720×1280。
- `resolution` 为正整数时按短边等比缩放；`null` 跳过这次保存前的额外缩放，不保证得到物理原生分辨率。按已核对的 schema 显式传值，不依赖会随版本变化的默认值。
- `region` 使用当前版本规定的缩放前坐标系。若支持转换元数据，使用实际返回的比例和裁剪原点；否则由已确认的完整截图/输出尺寸和实际裁剪范围建立映射。不清楚边界裁剪、偏移或比例时先确认，不能从小图猜绝对点击位置。
- 仅在已知变换是“等比缩放后裁剪”时，预览点可按 `controller_x = image_x * scale_x + crop_x`、`controller_y = image_y * scale_y + crop_y` 换回控制器坐标。这里的比例是“预览 → 控制器”，裁剪原点也是控制器坐标；窗口布局变化后旧映射失效。

## 选择返回什么

- `ocr()` 已自行截图。文字查询直接调用 OCR，脚本内筛到所需文字、框和分数；只取结构化结果的相关字段，避免完整结果对象和重复的 text/structuredContent 同时输出。
- 本地识别依然可以高频读取画面；限制的是送给模型的内容与调用往返。等待与轮询优先在 Pipeline 或有界脚本内做，只有业务分支、歧义或异常才返回模型判断。
- 原图留本地用于测量、模板与真实截图模拟；预览另外裁剪/缩小。不要为了模型看图改变控制器或生产识别分辨率，不覆盖证据原图，也不把 JPEG 预览直接当无损模板。
- 截图通常返回路径字符串；FastMCP 包装后可能在 `structuredContent.result` 中。先按实际结构提取路径或目标字段，不把整个工具返回值打印出来，也不假设有 `r.path`。
- 若选用的工具自动带图，先确认是否支持仅落盘返回路径或关闭图片输出，再取得文件做预算检查；没有可预检的模式时改用本地 OCR/识别或其他可先落盘的方式，不先把大图送入上下文再统计。
- 需要原图证据和预览时，保存一次原图后使用下节本地脚本生成预览，不新增图像服务或改第三方包。本地文件落盘本身不进入会话；只输出路径/摘要时不会把该文件中的像素或 base64 上传。

## 本地裁剪与坐标映射

当前 `screencap` 有 `region` 裁剪；没有自动确定业务 ROI、也没有可靠返回变换元数据时，使用此流程，不每次重新推导：

1. 首次观察通过 OCR 框或预算内概览确定业务 ROI，在任务记录保存完整控制器尺寸、区域 `[x,y,w,h]`、就绪标识与布局条件。后续布局未变时复用；窗口尺寸/缩放/布局变化时失效，不盲用旧 ROI。
2. 取得完整控制器图到本地：当前 schema 支持时用 `region: null, resolution: null`，只提取返回路径，不回传原图。确认这是完整控制器输出，不是已裁剪预览或录制器的底层原图。
3. 用本技能 `scripts/prepare_preview.py` 的 `prepare` 子命令裁剪、缩小并生成 JPEG。下列变量来自本轮截图尺寸、ROI 和根目录预算，脚本路径相对项目根目录：

```powershell
& .venv\Scripts\python.exe -B skills\maanop-explore\scripts\prepare_preview.py prepare `
  $sourcePath $previewPath --controller-size $width $height `
  --roi $x $y $w $h --short-side 480 --max-encoded-bytes $imageBudgetBytes
```

输出路径需以 `.jpg`/`.jpeg` 结尾，且不得已存在；原图不被覆盖。脚本要求源尺寸等于声明的完整控制器尺寸，先裁剪到图像边界内的实际区域，再只缩小不放大；如编码后仍超限继续缩小。变换以最终实际输出尺寸计算，不能把请求的短边值当成最终比例。

脚本同时写 `<previewPath>.json`，包含原图 SHA256、完整尺寸、请求 ROI、实际裁剪 ROI、预览尺寸、映射比例/原点和 base64 data URL 字节估算。只测 JPEG data URL，不包含工具文字、JSON 包装或宿主重编码；回传前仍检查整轮合计。

4. 从预览读出的点 `(u,v)` 使用元数据映射，脚本 `map` 只计算位置，不发送点击：

```powershell
& .venv\Scripts\python.exe -B skills\maanop-explore\scripts\prepare_preview.py map `
  $metadataPath $u $v
```

公式是 `x = u * actual_crop_width / preview_width + actual_crop_x`，`y = v * actual_crop_height / preview_height + actual_crop_y`。映射框时分别转换左上和右下边界；选择严格位于可点击区域内部的点，不把框边界当落点。脚本拒绝预览外点，以及舍入后越出控制器或实际裁剪 ROI 的点，不自动夹回边界。

坐标图不是实时状态。执行点击前再次确认页面与目标仍待处理；原图/映射不足、源图尺寸不符或发生布局变化时停止使用旧点。本地预览依赖项目已有 OpenCV/NumPy，不连接设备、不点击、不联网，不作为生产模板。

## 回传前检查

1. 先测准备发送的文件字节数，确认最终编码方式。原始图片为 `n` 字节时，base64 长度为 `4 * ceil(n / 3)`，还要加 data URL 前缀、JSON 包装和文字。
2. 以根目录单图/单轮上限检查本轮所有图片与文字之和。文件大小只是编码预算的输入，短边设置不是体积保证；宿主可能重新编码时注明估算口径，不宣称已测最终线上载荷。
3. 超限就缩小 ROI、降低预览尺寸、按需压缩或改用 OCR 摘要，检查后再回传；只保留必要的关键帧。原图不因预览压缩而被替换。
4. 宏执行中不要每次点击都调用 `image()`；在已验证路径中本地确认中间状态，遇到异常就结束宏并返回失败摘要。

## 会话与网络计量

- 能可靠定位当前聊天 rollout 时只读记录其基线和当前字节数，不统计所有聊天的总增长来冒充本任务增量；会话文件不可定位时记缺口。
- 仅记录文件大小不读取整份 rollout，更不为了计量把历史 base64 输出到上下文。触发根目录预警时先保存交接，按约定切换新聊天。
- 网络基线、结束值和峰值应注明采集工具、时间段、接口/进程范围以及是否包含其他应用。网卡总量只能作为含背景流量的参考，不能当作 Codex 精确上行。
- 交接时传递同一任务的累计测量值、尚余预算与未计量时段；新聊天只重设 rollout 基线，不清零本任务实际上行。没有前段测量就保留缺口，不能把后半段测量冒充全任务结果。
- 如能计量，接近上行预算时停止本轮探索的持续工具/模型请求，保存必要交接后结束，不改成高频文字轮询继续消耗；无法计量时继续遵守可检查的图片/输出/会话预算，并明确总上行未验证。不把 compact 当作删除图片、磁盘清理或流量达标证明。
