# MaaNOP 探索与验证

按“观察页面与状态 → 实现可验证的小段 → 运行验证 → 根据失败补查 → 交付”推进。沿用当前项目 `AGENTS.md` 的授权边界、失败语义和验证命令；技能调用不增加游戏操作权限。

## 确定本轮范围

用户负责说明新功能的大致业务流程；代理负责探索具体点击位置、识别方式、就绪标识和等待条件，不把这些实现问题交回用户。先从用户流程提取允许的起点、可观察的完成条件、返回状态和副作用范围。已有授权继续有效；仅对影响行为或验收的缺失选择提问。若用户只要求探索，到状态记录和待验证清单即交付，不自动进入实现。

读当前工作区的 `AGENTS.md`、`assets/interface.json` 中有关任务与资源路径，再针对性检查现有 Pipeline、图片和 Agent。复用已确认适用的组件；不要为探索自动生成全项目图谱、初始化整套工具或安装其他技能。

复用旧记录时核对对应版本、尺寸和画面。功能专属位置、文字误识别和时序只用于对应业务，不能提升成其他功能的默认参数。

首次用工具或版本变化时按 [MaaMCP 使用与预算检查](references/maamcp.md) 核对调用与坐标。记录按 [证据与交接](references/evidence.md) 整理；只在开始记录或交接时读取该参考。

## 管理员权限

本机游戏交互的点击、按键等操作需要管理员身份。首次操作前确认实际持有控制器的 MaaMCP/调试宿主进程已提升权限；单独提升一个执行脚本不代表现有 MaaMCP 服务也已提升。需要时在获准的管理员宿主中重新启动并连接服务，不关闭 UAC 或修改系统安全设置。

连接本项目 Windows 窗口时，默认显式使用 `screencap_method="PrintWindow"`、`mouse_method="Seize"`、`keyboard_method="Seize"`；点击一律使用 Seize。大厅的其他窗口（如多开对话框）同样，默认的后台截图在这些窗口上会返回旧帧。更换截图或输入方式须重新连接，后续调用使用新 controller_id，不复用旧控制器。Seize 会占用前台鼠标键盘。

权限未满足时先完成只读检查和可做的离线工作，说明需要用户完成的管理员启动动作，不通过反复试点来验证权限。管理员身份不代替游戏消耗或不可逆操作的业务批准。

## 探索一个可独立验证的小段

1. 先观察当前页面，区分已观察事实、用户选择、假设和未知。状态必须有截图、OCR 或识别记录支持；节点存在不证明当前已到达其前置页面。
2. 优先 OCR 或已有的无副作用识别；非文字、遮挡和歧义才补局部预览。导航后重新观察，保留会影响分支或点击时序的中间状态。
3. 每次未知跳转记录前置标识、点击目标、结果标识与证据，确认目标出现且可点击。批量调用仅用于已验证路径；执行中仍检查结果，异常就停止该批次。
4. 对当前小段观察起点、必要中间态、成功态，并确认安全返回或交接位置。返回也要识别验证。成功态需要消耗或不可逆操作才能出现时，先停在已确认的安全边界，按 `AGENTS.md` 取得批准再执行。
5. 未到达或只由推测支持的状态继续标为未验证。不因探索受限而伪造正常完成分支；可以交付部分探索，也可以先实现其他证据充分的小段。

无需等整个业务所有分支全部探索完才写第一段 Pipeline。每段的行为和验收必须已被证据覆盖，未完成的业务目标仍保持待办。

## 粗粒度 Pipeline 与首轮调试

根据用户说明和已观察的小段先形成粗粒度 Pipeline，把主要页面和转换连起来；识别与等待先采用有依据的保守条件。不要为了首版就猜出所有异常分支，也不要把用户的流程说明当作具体按钮已就绪的证据。

初稿完成并通过相关静态/资源检查后，在已授权范围内调试运行一遍。首轮执行前读取 [逐帧调试与页面就绪](references/debug-run.md)，开启 debug 并确认每次控制器实际截图都会落盘；仅开启错误截图不够。运行涉及未经批准的消耗或不可逆步骤时先停在安全边界，取得批准后再继续，不能借调试扩大权限。

首轮后按时间顺序核对全部界面转换，包括成功通过的转换：旧状态离开了吗、标题与按钮何时出现、资源/画面何时真正加载完成、什么标志能证明下一步可点击。依据原图和节点记录修改识别/等待，再验证受影响的小段；运行成功也不能跳过这次转换审查。

## 实现与验证细节

- 先检查公共导航、弹窗及返回节点的实际前置条件。默认用 Pipeline 表达已观察的有限状态流；是否引入 Python 按 `AGENTS.md` 判断。
- ROI 和点击范围来自本任务的真实证据。识别标识后固定位置点击可以使用，但须验证标识与目标就绪时序及坐标适用范围；不照搬社区返回节点、置信度或扩边值。
- OCR 候选有歧义时对实际画面做有界 ROI 对比，覆盖正例、易混淆画面和渲染差异。未知文本或状态不路由到消耗、删除或业务成功。
- 依据项目锁定的 maafw 核对字段。新版本 MaaMCP 能运行某协议，不代表项目部署环境也支持。GUI 选项改动同时检查任务注册、目标节点、覆盖结果及 Python 读取路径。
- 按根目录验证要求逐级检查：改动格式与 Schema、项目 `.venv` 资源加载、Custom 注册、真实截图的 `CustomController` 模拟，再做获准的实际运行。只运行与改动相关的检查；不在本地运行 `npx @nekosu/maa-tools check`。
- 模拟覆盖正常路径、丢点击、未变状态、延迟刷新及本任务相关失败分支。根据节点实际命中路径和业务后置条件判断，不以 `Succeeded` 或资源可加载代替验收。
- 未执行的检查写明原因和证据缺口；离线通过与游戏联调通过分别报告。

## 根据失败定点补查

先读失败节点及邻近路径、识别结果和有界日志，区分页面/前置状态错误、识别参数、点击落点或时序、配置覆盖及注册问题。日志只取有关节点和需要的上下文，不整份读取。

需要截图时先明确它要回答什么，例如“是否仍有确认框”“按钮是否已出现”。保存异常原图到本地，只回传回答该问题所需的预览或结构化结果。

每次重试前确认仍待处理，说明新依据和停止条件。优先复用本任务已有重试上限；没有时按风险设置一个小的有限上限并记录。达到上限或连续无新证据/进展时，换观察方法、缩小范围或报告阻塞，不持续盲点。未观察到的页面被暴露出来时，回到探索补证据再改节点。

## 交付与继续

持续更新一份当前任务记录，存到本项目已忽略的 `artifacts/<功能>-<日期>/`；测量数据和证据只保存在任务记录里，不写进节点注释；节点只保留参数本身和必要约束，任务记录引用节点中的参数，不复制维护同一参数。

每段结束及上下文预算预警时保存：当前稳定页面、已确认状态及证据、改动、验证结果、未知/阻塞、下一步和预算计量。没有实际网络测量就记“未测”，不从 rollout 推断实际上行或节省比例。

交付区分探索完成、局部实现、离线验证和实际端到端验收。业务完成条件未获证实就明确保留缺口。新聊天读取交接记录继续，不靠恢复旧图片历史重建知识。
